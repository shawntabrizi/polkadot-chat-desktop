# M2 — Live chat with a bot and a person

## Goal

With the self-owned identity from M1, the app sends a chat request to a
username, the peer accepts, and text flows both ways. Proven headlessly by
`npm run e2e:chat -- <username>`: it registers or reuses a test identity, sends
a request to the peer, waits for the accept, sends `ping <nonce>`, and passes
when a reply arrives within 120 s. The test peer is the bot `pcdpeer.47` on
`devnet` (the reviewer runs it; it auto-accepts and echoes or answers).

## Steps

1. **Domain code runs in Node.** The renderer domain must run outside the
   browser for the e2e script: Dexie with `fake-indexeddb` (already used in
   specs), `polkadot-api` WS provider from `polkadot-api/ws` (works in Node),
   `crypto.getRandomValues` and `crypto.randomUUID` (Node 20+ globals). Find
   every browser-only reference in `src/renderer/domain` and `src/renderer/app`
   (`window`, `document`, `localStorage`, `navigator`) and move it behind a
   small `platform` module `src/renderer/app/platform.ts` with a Node fallback.
   Do not change behaviour in the browser.

2. **Self identity in the manager.** The chat manager and request intake read
   the identity through `readUserIdentity()` and device keys through
   `getDeviceKeys()`. With M1's seeding both return the self-owned identity.
   Verify by reading the code; fix anything that still assumes a paired phone
   (for example a check on `peerStatementAccountId !== identityAccountId`).
   Record what you changed.

3. **e2e script.** Create `scripts/e2e-chat.mjs` (run through `tsx` like
   M1's script) and `"e2e:chat": "node scripts/e2e-chat.mjs"`:
   - Args: `<peerUsername>` and optional `--profile devnet|paseo`,
     `--identity <name>` (default `pcde2e`).
   - Identity: if `.agent-runs/identity-<name>/identity.json` exists (from
     M1's script) reuse it; otherwise register `<name><4 random digits>` with
     M1's `createIdentity` using the plain file store, and wait for attestation.
   - Seed Dexie (fake-indexeddb) with `seedSelfIdentity`.
   - Resolve the peer: username → account via the identity backend search
     (`src/renderer/domain/identity/search.ts`) or the People chain
     `UsernameOwnerOf` (see `.refs/bot-core/lib/people-directory.mjs`
     `usernameOwner`); then the peer's chat key via the directory. Print
     `PEER <accountHex> key_type=<byte>`; exit 3 with `PEER_KEY_UNSUPPORTED`
     when the byte is not 0.
   - Start the chat manager, send a chat request to the peer, print
     `REQUEST_SENT`. Wait up to 120 s for the accept (contact row appears);
     print `ACCEPTED`. If the contact already exists from a previous run, skip
     the request and print `CONTACT_EXISTS`.
   - Send `ping <random 6 hex>`; wait up to 120 s for any inbound message from
     the peer; print `REPLY <first 80 chars>` and `E2E_OK`; exit 0. On timeout
     print `E2E_TIMEOUT <stage>`; exit 4. Always close the WS provider so the
     process ends.
   - Log the statement-store connection state changes with a `[ws]` prefix.

4. **UI.** In `Search.tsx`, `Requests.tsx`, `Chats.tsx`, `Room.tsx` nothing
   should need to change. Run the app with `npm run dev`, create an identity
   (or reuse), search `hishawn`, send a request, and chat. If a screen breaks
   because of the self-identity, fix the screen. Write what you saw in
   `docs/acceptance.md`; if you cannot run the GUI, say so.

5. **Specs.** Add `scripts/e2e-chat.spec.ts` or a domain spec that runs the
   request-and-reply flow against `createInMemoryStatementStore` with two
   in-process identities (self and a fake peer built from
   `src/renderer/domain/testing/peers.ts`). This must pass offline.

6. **Run.** `npm run check`; `npm run e2e:chat -- pcdpeer.47` (the reviewer
   keeps the bot running; if it is down you will see `E2E_TIMEOUT accept` —
   paste it and continue).

## Do not

- Do not add group chat, files, or calls.
- Do not change the wire format or the SDK versions.

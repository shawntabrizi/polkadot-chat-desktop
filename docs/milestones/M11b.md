# M11b — Coin flip, balances in the UI, bot-declared balance

## Goal

(1) A **coin flip** contract chat: two people each stake 0.5 PAS through a
`tx` button in a room with the `pcdflip` bot; the contract settles with block
randomness and pays the winner; both see references and the bot narrates.
(2) **Your balance always visible**: a chip in the left-pane footer and a Pocket
panel. (3) **Bot-declared balance**: the meter header reads the contract the
bot's `botInfo.balance` hint names, and `src/shared/meter.ts` constants go
away. The pca half (another agent, same branch): the Flip contract, the
`pcdflip` bot, the `balance` hint in bot info for `pcdmeter`.

## Steps

1. **Balance hint.** Decode `botInfo.balance` (optional field, spec 0008 v2;
   an older `botInfo` without it must still decode). Room header for any bot
   with a hint: `label: value unit (~N replies)`, read at best block on each
   new block while the room is open, through a generic
   `chain:contractRead(chainId, contract, calldata)`. Delete `src/shared/meter.ts`
   and every meter constant; the meter e2e must still pass with the hint the
   bot now sends.
2. **Balance chip + Pocket.** Footer chip next to the username: the devnet
   Asset Hub free balance in mono ("12.3 PAS"), refreshed on new best blocks
   and after every signed tx; click opens a Pocket panel in the right pane
   (not a modal): balances per configured chain (Asset Hub; People chain
   shows "no balance needed" if the account holds nothing), the address with
   Copy and a QR (existing `QrCode.tsx`), and a "Get test funds" button that
   opens the Faucet chat. Spec for formatting (plancks → "1.234 PAS", 4 dp).
3. **Coin flip room.** The `pcdflip` bot sends a `buttons` message with one
   `tx` button "Stake 0.5 PAS" (kind 1 call `stake()` payable) and, once two
   stakes are in, posts a reference "Flip settled: <winner> won 1 PAS". The
   desktop needs nothing special beyond M11, plus: the bot's `balance` hint
   labelled "your stake" shows the user's current stake in the header.
4. **e2e.** `scripts/e2e-flip.mjs` → `"e2e:flip"`: two e2e identities (reuse
   `identity-pcde2e` and register `pcde2eb` if missing; both dripped via the
   faucet bot first), both request/accept `pcdflip`, both press Stake
   (dry-run → sign → `STAKED a|b`), then wait for the settlement reference
   (`SETTLED winner=<username> payout=1 PAS`) and check the winner's Asset
   Hub balance rose by ≈ 0.5 PAS minus fees (`FLIP_OK`). Exit 12 on timeout.
5. **Screenshots.** `pocket.png` (panel open), `room-flip.png` (stake
   button + strip) and `room-flip-done.png` (settlement reference) in both
   themes.
6. **Run**: `npm run check`, `npm run smoke`, `npm run e2e:meter` (still
   green without constants), `npm run e2e:flip`, `npm run screenshots`.

## Do not

- No modal. No gradient unless the design-system rule for identity objects is met; record the choice.
- Never sign without a dry-run.

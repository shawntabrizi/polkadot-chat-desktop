# M12h — Fix round: fast screenshot passes and small carry items

## Goal

A full screenshot pass under 3 minutes and a single-shot rerun in seconds
(owner ask 2026-09-24), plus the small items carried from M12e–M12g reviews.

## Read first

`scripts/screenshots.mjs` (the `--only` flag and fixture rows from M12e/M12i),
`docs/review/M12c.md` carry list, `docs/review/M12g.md` answers 2 and 5,

## Steps

1. **Both themes from one state.** Reach each state once; capture, switch
   the theme attribute, capture again. Never rerun a flow for the second
   theme.
2. **Fixtures for UI states.** Reference bubbles (submitted, in block,
   finalized, failed), keyboards, request/paid bubbles, diagnostics: render
   from fixed rows written to the throwaway profile (as M12e/M12i do), no
   chain, no bot. Only shots that prove a live flow keep the chain
   (flip, meter, group, faucet).
3. **Parallel live flows.** The live flows run in separate headless
   instances with their own identity and user data dir, at the same time.
4. **Measure** and record: full pass before/after in `docs/acceptance.md`.
5. **Carry items:** the chat-list pending row reads "Sent · just now" for
   15 s before "No answer yet" (matches the demo row); an incoming direct
   send bubble reads "checking…" until the chain shows the transfer, then
   "sent you 0.1 PAS"; the request button label keeps "Pay 0.5 PAS" and the
   caption beside it drops the duplicated amount; search results show reply
   rows; an over-limit keyboard aligns on reject. Each with a test.
6. **Run**: `npm run check`, `npm run smoke`, `npm run screenshots` (full,
   timed), `npm run screenshots -- --only room-tx-done` (timed).

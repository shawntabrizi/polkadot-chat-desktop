# M1 — Own identity: create a username without a phone

## Goal

The app mints an identity on this machine, claims a username on the People
chain through the identity backend (exactly as `pca create` does), stores the
mnemonic encrypted with Electron `safeStorage`, and seeds the renderer's device
and identity records from it. After M1 the Pair screen is no longer the entry
point: a Sign-up screen (username, two digits, availability check) creates
the identity, and the saved credentials are detected on the next launch. A Node script
`npm run identity:register -- <name>` does the same without the UI, for tests.

## Background you must understand

- Chat peers encrypt to the X25519 key published on chain in
  `Resources.Consumers` (RFC-0004 container `0x00 || x25519_pk || 32 zero bytes`).
  Registration publishes it. See `.refs/bot-core/docs/explanation/protocol.md`
  section "The on-chain identifier_key".
- A `pca` bot is one device whose Statement Store account IS its identity
  wallet account (`//wallet` sr25519 from the mnemonic). This app does the same:
  single device, device statement account = identity wallet account. That is
  why no phone and no delegation are needed.
- The web client models a *paired* identity: `UserIdentityRow` +
  `secrets['identity.chatPrivateKey']` + `DeviceRow` +
  `secrets['device.statementSeed']` + `secrets['device.encryptionPrivateKey']`
  (see `src/renderer/app/database.ts`). For a self-owned identity we fill the
  same rows so nothing downstream changes:
  - `device.statementSeed` = the identity wallet's 64-byte sr25519 secret
  - `device.encryptionPrivateKey` = the identity chat X25519 private key
  - `identity.chatPrivateKey` = the same identity chat X25519 private key
  - `userIdentity.identityAccountId` = `rootAccountId` = wallet public key
  - `userIdentity.peerDeviceEncPubKey` = own encryption public key
  - `userIdentity.peerStatementAccountId` = own wallet public key

## Steps

1. **Dependencies.** Add, pinned to the versions `.refs/bot-core/package.json`
   uses: `@scure/sr25519`, `@polkadot-labs/hdkd-helpers`,
   `@novasamatech/substrate-slot-sr25519-wasm` (only if `wallet-keys.mjs`
   needs it), and `@scure/bip39` (newest older than three days) for mnemonic
   generation. Record versions in `docs/decisions.md`.

2. **Copy the wasm.** Copy `.refs/bot-core/vendor/summit-bandersnatch-cli.wasm`
   to `resources/summit-bandersnatch-cli.wasm`. Configure `electron.vite.config.ts`
   so `resources/` is available to the main process at runtime in both dev and
   build (`process.resourcesPath` in a packaged app, repo path otherwise). Put
   the path resolution in one function `resourcePath(name)` in
   `src/main/resources.ts`.

3. **Port the key derivation.** Create `src/main/identity/keys.ts`:
   `generateMnemonic()`, `deriveIdentityKeys(mnemonic)` returning
   `{ accountId, walletSecret64, chatPrivateKey, chatPublicKey, identifierKey65, liteEntropy, sign }`
   with the same math as `deriveIdentityKeys` in `register.mjs` and the
   X25519 helpers in the codec. Copy the needed functions from
   `wallet-keys.mjs` and `app-chat-codec.mjs` into
   `src/main/identity/crypto.ts` with the required header comment. Add
   `keys.spec.ts`: a fixed test mnemonic yields the same `accountId` and
   `chatPublicKey` on every run, and `identifierKey65[0] === 0` with 32
   trailing zero bytes. Use a mnemonic generated in the test; never a real one.

4. **Port registration.** Create `src/main/identity/register.ts` from
   `register.mjs`: `requestIdentityChallenge`, `obtainIdentitySession`,
   `acquireIdentitySession`, `registerIdentity`, `waitForAttestation`,
   `runLitePerson` (the `node:wasi` runner; point it at `resourcePath('summit-bandersnatch-cli.wasm')`).
   Keep the HTTP payloads byte-for-byte the same as the source. Typed with
   explicit interfaces for the backend responses you can see in the source;
   `unknown` + narrowing where the source uses loose objects.

5. **People directory.** Create `src/main/identity/directory.ts` with
   `consumerOf(accountHex)` and `identifierKeyFor(accountHex)` using
   `polkadot-api` + the People descriptor, same as `people-directory.mjs`
   `createChainDirectory`. Endpoints come from the network profile (copy
   `NETWORK_PROFILES` into `src/shared/network.ts` and make the renderer's
   `app/network.ts` re-export it, so main and renderer share one table). Add
   `DEFAULT_BACKENDS`-style `identityBackend` per profile (already in the table).

6. **Encrypted store.** Create `src/main/identity/store.ts`:
   `saveIdentity({ mnemonic, username, accountHex, profile })` writes
   `<userData>/identity.json` with `{ version: 1, username, accountHex, profile, mnemonicEncrypted: <base64 of safeStorage.encryptString(mnemonic)> }`.
   `loadIdentity()` returns `null` when the file is missing, otherwise decrypts.
   If `safeStorage.isEncryptionAvailable()` is false, throw with a clear
   message; do not fall back to plaintext.

7. **Registration flow.** Create `src/main/identity/service.ts` with
   `createIdentity({ username, digits, profile, onProgress })`:
   a. `mnemonic = generateMnemonic()`; keys = `deriveIdentityKeys`.
   b. `session = acquireIdentitySession({ backendUrl, mnemonic })` (devnet
      needs it; on `paseo` skip when the backend has no challenge endpoint,
      mirroring `cli.mjs`).
   c. `registerIdentity({ mnemonic, username, digits, backendUrl, identityToken })`.
   d. `saveIdentity(...)` immediately after the backend accepts (before waiting).
   e. `waitForAttestation(directory, accountHex, { timeoutMs: 180000, onTick })`.
   f. Return `{ username, accountHex, identifierKeyHex }`.
   Progress strings go to `onProgress` for the UI. Errors are `Error` with
   messages a user can read.

8. **IPC.** Create `src/main/ipc.ts` and register handlers:
   - `identity:get` → `{ username, accountHex, profile } | null`
   - `identity:available` `(username: string)` → `{ status: 'AVAILABLE' | 'TAKEN', availableDigits: number[] }`
   - `identity:create` `({ username, digits: string | null, profile: 'devnet' | 'paseo' })` → result of step 7
   - `identity:secretsForRenderer` → `{ statementSeed: Uint8Array (64), chatPrivateKey: Uint8Array (32) }`
     derived from the stored mnemonic. This is the only channel that carries
     secrets; it exists so the renderer can seed Dexie. Document that in a
     comment. Never send the mnemonic.
   - `identity:progress` events (main → renderer) with the progress strings.
   Extend `src/shared/desktop-api.ts` and `src/preload/index.ts` with typed
   wrappers for each channel.

9. **Renderer seeding.** Create `src/renderer/domain/identity/selfIdentity.ts`:
   `seedSelfIdentity(secrets, accountId)` writes the rows listed in
   "Background" into Dexie (device row, three secrets, userIdentity row) inside
   one transaction. Change `getDeviceKeys()` in `device/repository.ts` so it
   never mints keys when a `device.statementSeed` secret already exists (read
   the current code; keep its cache). Add a spec with `fake-indexeddb`.

10. **Sign-up screen.** Create `src/renderer/ui/SignUp.tsx`. This is what a
    user with no account sees on launch. It mirrors the mobile app's username
    flow:
    a. **Username input.** Lowercase letters only, 6 to 29 characters (the
       mobile app filters to letters and lowercases). Header "Welcome to
       Polkadot" / "Choose a username to get started."; title "Pick a
       username"; placeholder "Enter username"; hint "Minimum 6 characters";
       button "Get username".
    b. **Digits picker.** Two digits `00`–`99` (the on-chain form is
       `name.NN`, see `canonicalUsername`). Default: "Let the network pick"
       (send no `preferredDigits`). The user may also choose a number.
    c. **Availability check.** When the username is valid and the user pauses
       typing (300 ms), call `identity:available(username)` (new IPC). Main
       does what the mobile app does: `POST {backend}/api/v1/usernames/available?version=v1`
       with body `{"usernames":["<name>"]}`. Response:
       `{"_tag":"v1","value":{"<name>":{"status":"AVAILABLE","availableDigits":[11,23,42]}}}`
       (status may also be `TAKEN`). Show "It's yours!" when available, "Taken.
       Try another." when not. Pre-fill the digits field with the first entry
       of `availableDigits`; the user may type another value, validated
       against that list ("Digits taken. Try again."). "Let the network pick"
       sends no digits. Cache per name for 60 s. Do NOT use the search
       endpoint for this.
    d. **Network select.** `devnet` default.
    e. **Sign up button.** Disabled until the name is valid and the chosen
       number is not taken. On click call `identity:create({ username, digits, profile })`
       and show the progress lines from `identity:progress`
       ("Creating keys", "Claiming username", "Waiting for the network").
    f. **Result.** On success call `seedSelfIdentity`, then show Chats with the
       final username (the backend may assign a different number when none
       was chosen: show the one it returned).
    g. **Errors** are shown under the button in plain words; the button
       re-enables.
    `identity:create` passes `digits` as `preferredDigits` exactly as
    `registerIdentity` does.

    **Detect on next launch.** The credentials saved by step 6 are the
    account. In `App.tsx`: on start call `window.desktop.identity.get()`;
    if null show SignUp; if present and Dexie has no `userIdentity` row,
    fetch `identity:secretsForRenderer()` and seed, then show Chats. Keep
    `Pair.tsx` in the tree but unreachable from the UI (delete its route/tab).

11. **Node script.** Create `scripts/identity-register.mjs` that runs the
    main-process registration without Electron: it takes `<username>` and
    optional `--profile`, uses a plain in-memory store instead of `safeStorage`
    (write `identity.json` unencrypted under `.agent-runs/identity-<name>/`
    which is git-ignored), prints `username`, `accountHex`, `identifierKeyHex`,
    then queries the directory and prints `ON_CHAIN key_type=<first byte>`.
    Wire it as `"identity:register": "node scripts/identity-register.mjs"`.
    The script imports the TypeScript sources through `tsx`
    (add `tsx` as a devDependency) or through the built `out/main`; choose one
    and record it.

12. **Run.** `npm run check` green. `npm run smoke` still prints `SMOKE_OK`.
    Then register a test identity on devnet:
    `npm run identity:register -- pcdtest<4 random digits>`. Paste the output
    into `docs/acceptance.md` (it contains no secret). If the backend refuses
    or times out, paste that and continue; do not retry more than twice.

## Do not

- Do not send the mnemonic or seeds to the renderer except through
  `identity:secretsForRenderer`. Do not log them anywhere.
- Do not implement recovery from a typed mnemonic (v2).
- Do not touch chat, requests, or messaging code.

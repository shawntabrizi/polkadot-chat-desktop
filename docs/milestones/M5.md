# M5 — UI pass: the Polkadot design system, a desktop chat layout

## Goal

The app looks and feels like a finished Polkadot desktop chat client, so it can be
evaluated on its own merits. Adopt the official Polkadot design system (tokens,
five themes, stock shadcn components, Lucide icons, Inter/Manrope/Martian Mono),
lay the app out as two panes like Telegram Desktop and Polkadot Desktop, and
rebuild every screen on it: sign-up, chat list, room, requests, search,
assistant, settings. Behaviour and domain code do not change. Proven by
`npm run check`, `npm run smoke`, a token lint, and `npm run screenshots`, which
writes PNGs the reviewer looks at.

## Read first (all of it, in this order)

1. `.refs/polkadot-design-system/SKILL.md` — the rules. Read every section.
   The reviewer checks against it.
2. `.refs/polkadot-design-system/assets/theme/README.md`, `assets/theme/*.css`,
   `assets/theme/theme.ts`, `assets/shadcn/cn.ts`, `assets/shadcn/components.json`,
   `references/design-tokens.md`, `references/shadcn.md`, `references/copy-patterns.md`.
3. Polkadot Desktop's chat UI, the geometry to copy:
   `.refs/polkadot-desktop/src/features/chat/ui/ChatFullscreen.tsx`,
   `partials/ChatItem.tsx`, `partials/MessageBubble.tsx`, `partials/MessageFlow.tsx`,
   `partials/MessageInput.tsx`, `partials/RequestBanner.tsx`, `partials/NewRequestsItem.tsx`,

5. `docs/reference/mobile-ux.md` (written by the reviewer: the strings and the
   chat conventions of the phone apps). Use its strings verbatim.

## Steps

1. **Design system setup** (SKILL.md §1, do it exactly):
   a. Copy `.refs/polkadot-design-system/assets/theme/` to `src/renderer/theme/`.
      Do not hand-write tokens.
   b. Add Tailwind v4: `tailwindcss` and `@tailwindcss/vite` (newest older than
      three days, pinned). Add the plugin to the renderer section of
      `electron.vite.config.ts`. Create `src/renderer/index.css` with
      `@import "tailwindcss"; @import "./theme/index.css";` and import it from
      `main.tsx`.
   c. Copy `assets/shadcn/cn.ts` to `src/renderer/lib/cn.ts` and
      `assets/shadcn/components.json` to the repo root; adjust its paths so
      components land in `src/renderer/components/ui/` and the `cn` alias
      points at `src/renderer/lib/cn.ts` (tsconfig `paths` + vite
      `resolve.alias`; see the SKILL.md warning about the bare `cn` specifier).
      Install with `npx shadcn add button input select textarea badge avatar
      tooltip dropdown-menu sonner scroll-area separator`. Never `alert-dialog`.
      Never hand-edit `components/ui/`.
   d. Fonts: the `<link>` from `theme/README.md` in `src/renderer/index.html`,
      plus the anti-flash script from the same README. Default theme: none set
      (Berlin Day following the OS to Berlin Night). No `dark:` colour classes
      anywhere in your code.
   e. Icons: `lucide-react` (pinned). No other icon set, no emoji as icons
      (reaction emoji are content, not icons).
   f. `cn.ts` class groups must include the theme's named styles (the file
      already does; verify after `shadcn add` that the alias resolves to it).

2. **App shell** (`src/renderer/ui/App.tsx` + new `ui/Shell.tsx`): two panes on
   `bg-surface-main` with `p-2 gap-2` like Polkadot Desktop. Left pane, 320px:
   a header row with the app name and a `+` (new chat) icon button, a search
   field ("Type username"), the "New requests" pill (only when pending > 0,
   with a count badge), the chat list, and at the bottom a small row with the
   user's avatar + username and a Settings icon button. Right pane: the room,
   or an empty state "No chat selected" / "Select a chat to view the
   conversation". No tabs. Requests, Search and Settings open in the right pane
   or in a side panel (SKILL.md §10 "Avoid Modals"), never a modal. Keep
   `Pair.tsx` unreachable.

3. **Sign-up** (`ui/SignUp.tsx`): centred card on `bg-surface-main`
   (`bg-surface-container rounded-container shadow-1`, max 440px): the
   Polkadot symbol logo (copy `assets/logo/logo-symbol_dark.svg` and
   `_light.svg` to `src/renderer/public/` and render the theme-aware pair per
   SKILL.md §9), "Welcome to Polkadot" as `text-display-l`, "Choose a username
   to get started." as `text-body-l text-fg-secondary`, the username Input,
   the availability line ("It's yours!" in `text-fg-success`, "Taken. Try
   another." in `text-fg-error`, "Minimum 6 characters" in `text-fg-tertiary`),
   the digits control (a Select of the offered numbers with "Let the network
   pick" as the first option), the network Select, the consent line with
   Terms and Privacy links (`text-fg-link`), and one primary pill CTA "Get
   username" (`rounded-full px-9 py-3.5 h-auto text-label-l font-semibold w-full`,
   the bottom action slot). Progress lines replace the CTA while creating;
   errors in `text-fg-error` under it.

4. **Chat list rows** (`ui/ChatList.tsx`, `ui/ChatRow.tsx`): copy ChatItem's
   recipe: avatar 40px with a deterministic tone from the username (port
   `helpers/avatar.ts` `getAvatarTone`; avatar tokens are theme-invariant),
   name `text-label-l`, time `text-caption text-fg-tertiary` ("Now", "5m",
   "3h", "Yesterday", else date), preview `text-body-m text-fg-secondary`
   ("You: …" prefix for own), unread count `Badge` on the right, `rounded-nested`
   row with `hover:bg-selection-container-hover`, selected row
   `bg-selection-container-active`. The Assistant row is first with a
   `Sparkles` icon avatar. Empty state: "No active chats" / "Start a
   conversation with someone by typing their username".

5. **Room** (`ui/Room.tsx` split into `RoomHeader`, `MessageFlow`,
   `MessageBubble`, `Composer`): header with avatar, username, and a subtle
   status line ("Bot" for `pca` peers is unknown; show nothing); message flow
   with date separators ("Today", "Yesterday", date) and the mobile grouping:
   consecutive messages from one side share a group, tighter corners inside a
   group, a 4px tail corner on the last; own bubbles right on
   `bg-surface-container-inverted text-fg-primary-inverted`, peer bubbles left
   on `bg-surface-nested`; delivery ticks Lucide `Clock` (sent), `Check`
   (delivered to store), `CheckCheck` (acked) in `text-fg-tertiary-inverted`;
   "(edited)" caption; reply quote block inside the bubble; reaction chips
   under the bubble (`rounded-full bg-surface-container text-label-s`); the
   quick reaction row 👍 ❤️ 😂 😮 😢 🙏 🔥 👏 on hover/right-click plus Reply,
   Copy text, Edit in a `DropdownMenu`; markdown body from the existing
   renderer with `markdown.css` ported to tokens. Composer: a Textarea that
   grows to 6 lines, placeholder "Write a message…", Enter sends, Shift+Enter
   newline, a send icon button (`rounded-full` circle, `SendHorizontal`),
   reply banner "Reply to <name>" with an X. Assistant room: "Thinking…" as
   `text-fg-tertiary` shimmer text, a Stop button while streaming.

6. **Requests** (`ui/Requests.tsx`): the recipient banner replaces the composer
   in that room: "Accept chat request from <name>" / "Add <name> to your
   contacts to accept the chat request. They won't know you've seen their
   message until you accept." / Decline (secondary) / Accept (primary,
   `rounded-medium`). The requests list in the left pane replaces the chat
   list while open, with a back arrow. Sender side: after sending, the
   composer shows "Wait for <name> to accept your request message before
   sending the next message." System rows "<name> approved your request".

7. **Search / new chat** (`ui/Search.tsx`): typing in the left-pane search
   filters chats; the `+` button opens a "New chat" panel: Input "Type
   username", results as rows (avatar, name), a row click opens a draft room
   with the invite hint "Invite <name> to chat" / "You can only send one
   message in this request." and a "Send Request" primary button. "No results
   for “<q>”" empty state.

8. **Settings** (`ui/Settings.tsx`) in the right pane: sections as
   `bg-surface-container rounded-container` blocks with `text-heading-s`
   titles: Identity (username as `text-label-l`, account shown only behind a
   "Show account" toggle in `font-mono` with Copy; "Created on this computer";
   network), Appearance (theme Select with the five themes + "System", wired
   to `theme.ts` `setTheme`), Assistant (model, base URL, key input with "key
   stored", Test button), Danger ("Reset identity" as a Danger button,
   `rounded-medium`; no confirm dialog: act, then a Sonner toast "Identity
   reset" with Undo for 8 s that restores `identity.json` from a `.bak` the
   main process keeps until the grace period ends — add `identity:resetUndo`
   IPC).

9. **Copy pass** (SKILL.md §11): no raw hex or account ids as labels anywhere
   except behind "Show account". No "something went wrong": every error says
   what happened and what to do. List every string you changed in
   `docs/decisions.md`.

10. **Token lint**: add `scripts/check-tokens.mjs` (`"check:tokens"`) that
    fails when `src/renderer/**` outside `components/ui/` contains: `style={{`,
    a raw Tailwind colour class (`bg-(white|black|gray|zinc|neutral|slate|blue|red|green)-`),
    `dark:`, `font-bold`, `text-(sm|xs|base|lg|xl)` , `rounded-(md|lg|xl)`,
    `border-gray`, `#[0-9a-f]{6}` in `.tsx`. Add it to `npm run check`.

11. **Screenshots**: `scripts/screenshots.mjs` (`"screenshots"`): builds, runs
    the app with `PCD_USER_DATA_DIR=<tmp>` via the Chrome DevTools protocol
    (the pattern from `.agent-runs/m4/gui.mjs` if present, else write it), and
    saves 1280×800 PNGs to `.agent-runs/screens/<theme>/`: `signup.png`,
    then, with a seeded identity (`PCD_SCREENSHOT_IDENTITY=<path to an
    identity.json from .agent-runs/identity-*/>`), `chats.png`, `room.png`
    (the pcdpeer room with a few messages: send "hello" and wait for the
    echo), `assistant.png`, `settings.png`, `requests.png`. Run it for
    `berlin-day` and `berlin-night` (set `data-theme` via `setTheme`). If the
    bot is not reachable, capture what you can and say so.

12. **Run**: `npm run check` (now includes `check:tokens`), `npm run smoke`,
    `npm run screenshots`. Look at your own screenshots (Read the PNGs) and
    fix what looks wrong before you commit: overflow, clipped text, missing
    hover, misaligned edges (SKILL.md §10 "Every edge answers another").

## Do not

- Do not change domain code, IPC, or the protocol. UI only (plus the two new
  IPC calls named in step 8).
- Do not add tr-ui, Radix beyond what shadcn installs, styled-components,
  emotion, or a router.
- Do not add a modal for anything.
- Do not use the accent blue.

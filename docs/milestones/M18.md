# M18 — Profiles: several identities on one Mac, side by side (owner ask 2026-09-24)

## Goal

Like Element's `--profile`: a profile is a self-contained data directory
(`<userData>/profiles/<name>/`: encrypted mnemonic, local database, settings,
the published agent's state, temp copies). One process per open profile;
two profiles run side by side in two windows. A picker at launch when more
than one exists; Settings › Profiles to add, rename, remove, set the default.
The existing single profile migrates to `profiles/default/` on first start.

## Read first

- `src/main/index.ts` (single-instance lock, user data dir, `PCD_USER_DATA_DIR`,
  `--smoke`/`--agent-selftest` flags), `src/main/identity/store.ts`
  (safeStorage, where the mnemonic file lives), `src/main/agent/service.ts`
  (agent state dir, bot-core child, bridge port), `src/main/storageKey.ts`
  (at-rest key), `src/renderer/app/database.ts` (Dexie name), notifications
  (`src/renderer/ui/notifications.ts`), `scripts/lib/app.mjs` (how tests
  launch with a data dir), `docs/decisions.md` tail, `.refs/polkadot-desktop`
  if it has a profile switcher (check), and Element Desktop's `--profile`
  behaviour from its public docs (cite).

## Steps

1. **Layout and migration.** `profiles/<name>/` holds everything per
   profile; `profiles.json` at the root lists names, display data (username,
   network, avatar tone) and the default. First start with the old layout
   moves the old files into `profiles/default/` atomically (copy, verify,
   then remove), and records the migration. `PCD_USER_DATA_DIR` keeps
   pointing at the root; `PCD_PROFILE` (env) and `--profile <name>` (flag)
   pick a profile; headless tests keep working with one implicit profile.
2. **Per-profile process.** The single-instance lock is keyed by profile
   (`requestSingleInstanceLock({ profile })` or a lock file per profile);
   "Open in new window" spawns the app binary (`process.execPath`) with
   `--profile <name>`; opening a profile that is already running focuses
   its window instead. Debug ports, the agent's bridge port and bot-core
   state are per profile. Notifications carry the profile's username in the
   title when more than one profile exists; the dock badge sums unread
   across open windows (through a small IPC between processes, or per
   window if simpler; say which).
3. **Picker and settings.** With one profile: unchanged. With more: a
   picker view (no modal; the same pane style as sign-up): rows with avatar,
   username, network, "Open" (this window), "Open in new window", "Add
   profile" (runs sign-up into a new profile directory in this window), a
   running mark on profiles already open. Settings › Profiles: list, rename
   (display only; the directory name stays), "Remove…" (Undo toast for 6 s,
   then the directory is deleted; a running profile cannot be removed),
   default at launch, "Open another profile".
4. **Safety.** The same identity is never opened twice; removing a profile
   reminds the person that the recovery phrase is the only backup (link to
   the existing export); the at-rest key stays app-wide (safeStorage) and
   per-profile files are sealed with it as today.
5. **Tests.** Migration (old layout → profiles/default, idempotent), lock
   per profile, flag and env precedence, picker logic (running marks), the
   agent state dir per profile. e2e `scripts/e2e-profiles.mjs` →
   `"e2e:profiles"`: headless, one root dir: create profile A (sign-up),
   create profile B, launch both processes at once with `--profile`, each
   answers its own identity through the domain, B messages A over the real
   network (pcdpeer.47 as a third party is not needed), A receives:
   `PROFILES_OK`. Screenshots `profile-picker.png`, `settings-profiles.png`
   both themes.
6. **Run**: `npm run check`, `npm run smoke`, `npm run e2e:profiles`,
   `npm run smoke:packaged` (the packaged app must still start and migrate).

## Do not

- Do not edit `docs/spec/*.md` or `docs/milestones/*.md` (questions in
  `docs/questions.md` "## M18").

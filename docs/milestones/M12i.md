# M12i — Demo mode: one button that starts chats with the demo bots

## Goal

A new person should see who they can talk to without discovering anyone.
After the username is claimed, a step "Try the demo bots" lists the fleet
with one line each and one button that sends chat requests to all of them.
The same button lives under Settings › Demo. The bots (pca, running on the
owner's VPS) accept and greet, so the list fills within seconds. A bot that
does not answer shows "No answer yet" on its row (M12e), never an error.

## Steps

1. **Manifest.** `src/shared/demoBots.ts`: per network profile, a list of
   `{ username, tagline, tag: 'assistant'|'game'|'payments'|'utility' }`.
   Devnet has the fleet above; paseo has none (the step is hidden). A
   `PCD_DEMO_MANIFEST_URL` (env or setting) MAY point to a JSON with the same
   shape, fetched by the main process with a 5 s timeout and validated;
   the built-in list is the fallback. Spec the validation.
2. **Onboarding step.** After "It's yours!", a screen "Meet the demo bots":
   the rows (avatar tone from the username, name, tagline, tag chip), one
   primary button "Start chats with all", a ghost "Skip". Pressing sends a
   chat request to each username in order (lookup, then `sendChatRequest`
   with the opener "Hi!"), shows per-row progress (sent / accepted / no
   answer yet), and moves to the chat list after the first accept or after
   5 s, whichever first. A username that fails to resolve shows "Not on this
   network" and is skipped.
3. **Settings › Demo**: the same list and button ("Start chats" per row and
   "Start all"); rows already in the chat list show "Chatting". A "Remove
   demo chats" ghost button deletes those rooms locally (M12e delete).
4. **Idempotent**: never send a second request to a bot with a pending
   request or an open room.
5. **e2e**: `scripts/e2e-demo.mjs` → `"e2e:demo"`: fresh test identity,
   run the demo action through the domain, expect ≥ 4 accepts within 60 s
   (`DEMO_OK n=…`), and a second run sends nothing (`DEMO_IDEMPOTENT`).
6. **Screenshots**: `demo-onboarding.png`, `settings-demo.png`, both themes
   (fixture rows are fine for the list; the progress states need no bot).
7. **Run**: `npm run check`, `npm run smoke` (headless flags), `npm run
   e2e:demo`, screenshots.

# M14 — DAO chat: a group with a contract (proposals, staked votes, execution)

## Goal

A v2 group whose admin is a DAO bot. Members create proposals in chat,
vote with a staked `tx` button (spec 0007), and the contract executes the
outcome; the bot narrates and pins the live proposal. Everything a person
sees is a message, a button or a reference. pca half: the Dao contract
(Solidity → PolkaVM, `forge build --resolc`, deployed on devnet Asset Hub
like Meter and Flip) and the `pcddao` bot (a v2 group admin). Desktop half:
`tx` buttons pressable in v2 group rooms (the signing strip works in a
group; the reference goes to the group topic as content), a proposal card
rendered from the bot's messages, and the e2e.

## Contract (`contracts/dao/Dao.sol`)

- `propose(bytes32 groupId, string title, address target, uint256 value, bytes data, uint64 deadline) → proposalId`;
  a proposal is bound to a group id (the bot registers members' accounts).
- `vote(proposalId, bool support) payable`: the stake is the vote weight
  (min 0.1 PAS); one vote per account per proposal; refundable after the
  deadline via `withdraw(proposalId)`.
- `execute(proposalId)`: after the deadline, if yes > no, performs the call
  (a transfer from the DAO's balance in v1) and marks it executed.
- Events: Proposed, Voted, Executed, Withdrawn. Note: `docs/spec/contracts/dao.md`.

## Steps — pca

1. Contract + deploy script + note. Worst-case limits per the 0007 rule.
2. `pcddao` bot (v2 group admin, echo or haiku brain for narration):
   `/propose <title> | <amount> PAS to <username>` creates the proposal on
   chain (the bot pays) and posts a proposal message with two `tx` buttons
   "Vote yes (stake 0.1 PAS)" / "Vote no (stake 0.1 PAS)" and a `url`
   button "View on Subscan"; pins it; on each Voted event posts a tally
   line (edits the pinned message when edits exist, else a new line);
   after the deadline anyone presses "Execute" (a tx button) or the bot
   executes itself if funded; "Withdraw stake" buttons after the deadline.
   `/proposals` lists open ones. Budget: one statement per event.
3. Live proof `scripts/e2e-dao.mjs`: throwaway identities A (owner), B, C
   and the bot: create group, `/propose`, A and B vote yes, C votes no,
   deadline (short, e.g. 90 s), execute, B withdraws: `DAO_LIVE_OK`.

## Steps — desktop

1. `tx` buttons pressable in v2 group rooms; the signing strip and the
   reference bubble work in groups; the reference goes on the group topic.
2. A proposal card: the bot's proposal message renders with the tally line
   from the latest bot update, the buttons, the deadline countdown, and
   "Executed" state; pinned at the top (M16b pin bar).
3. `scripts/e2e-dao.mjs` → `"e2e:dao"` with two desktop identities and the
   pca dao bot run from a scratch workspace: `DAO_OK`.
4. Screenshots `room-dao.png` both themes.

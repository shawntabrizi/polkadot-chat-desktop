# M11 — Transactions in chat (spec 0007) and the pay-as-you-go agent

## Goal

Press a `tx` button, see the dry-run and the fee, sign with the chat identity's
key, and watch the reference bubble go submitted → in block → finalized. First
contract chat: a **pay-as-you-go agent** (`pcdmeter` bot) backed by a small
Revive contract on devnet Asset Hub: Top up buttons, a balance line in the room
header, metered replies that stop at zero. The `pca` half (another agent, same
branch) builds the contract, deploys it from `//Alice`, and runs the bot. Coin
flip is M11b, after this passes.

## Steps (desktop)

1. **Asset Hub connection.** Generate papi descriptors for devnet Asset Hub
   (`wss://asset-hub-paseo-rpc.n.dwellir.com`, fallbacks from
   `.refs/polkadot-app-deploy` environments), same metadata-cache and
   best-block rules as the People connection (`src/main/chain/assetHub.ts`).
   Expose IPC `chain:dryRun(intent)`, `chain:sign(intent)`, `chain:watch(hash)`.
2. **Codec.** `TxIntent` (Action tag 3 payload) and kind 245
   `transactionReference` per the spec; decode both vectors from
   `vectors-0007.md` byte for byte (poll as before).
3. **Signing strip.** Pressing a `tx` button opens an inline strip under the
   bubble: title, description, amount/asset, "Fee ≈ 0.0012 PAS", the signer
   ("shawntest.30"), the dry-run outcome ("Balance after: 1.0 PAS" from the
   decoded return or the revert reason in `text-fg-error`), Sign (primary,
   `rounded-medium`) and Cancel. Sign → main signs with the identity wallet
   key (`Revive.call` for kind 1, raw call for kind 0, `utility.batchAll` for
   several, `Revive.map_account` prepended once if unmapped) and submits.
4. **References.** Post `transactionReference` to the peer at each state and
   render it as a bubble: "Top up · submitted", then "in block #N", then a
   finalized tick, or "failed: <reason>"; Copy hash. Incoming references from
   the bot render the same way. Never wait for finality to update the UI.
5. **Meter header.** When a peer's `botInfo` has a command `balance`, or the
   bot sends a reference with note starting `balance:`, show "Balance: 0.8 PAS
   · ~4 replies" under the bot's name (read the contract at best block through
   `chain:read` with the ABI in `docs/spec/contracts/meter.md`). Keep it simple:
   a `chain:contractRead(address, calldata)` IPC returning bytes; the renderer
   decodes `uint256`.
6. **Faucet.** The Faucet contact gains a real "Get 1 PAS" `tx`-free path: it
   sends the user's address to the reviewer-run faucet bot `pcdfaucet` as a
   text command (`/drip <address>`); the bot transfers from `//Alice` and posts
   a reference. (Bot half: pca agent.)
7. **e2e.** `scripts/e2e-meter.mjs` → `"e2e:meter"`: with the e2e identity,
   `/drip` from `pcdfaucet` (expect a reference with status ≥ 1 within 90 s:
   `DRIP_OK`), then request/accept with `pcdmeter`, press "Top up 1 PAS"
   (dry-run → sign → reference: `TOPUP_OK`), read the balance (`BALANCE …`),
   ask three questions and watch the balance drop (`METERED_OK`), print
   `METER_OK`. Exit 10 on any timeout.
8. **Screenshots.** `room-tx.png` (the signing strip open) and
   `room-tx-done.png` (a finalized reference and the balance header) in both
   themes, from the room-peer test identity with an `e2e-chat.mjs --tx` flag
   (a `tx` intent for a plain balance transfer of 0.01 PAS to itself; the
   reviewer's dev identity is funded by the faucet first).
9. **Run**: `npm run check`, `npm run smoke`, `npm run e2e:meter`, `npm run screenshots`.

## Do not

- Never sign without a dry-run. No modal. No ETH-RPC (Substrate extrinsics only).
- Do not store keys anywhere new; signing happens in main with the existing identity key.

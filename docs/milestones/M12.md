# M12 — Groups (spec 0009, fan-out v1)

## Goal

A three-person room on devnet with a bot in it. Desktop half: create a group
from the New chat panel (pick members from contacts), send and receive wrapped
messages, roster changes, leave, a members panel; everything in one room. The
`pca` half (another agent, same branch): a bot accepts group invitations,
stores rosters, answers by fanning out, keeps per-group context.

## Read first

- `docs/spec/0009-groups.md` (authoritative), `0008-bot-info.md`, `0006-buttons.md`,
  `docs/spec/kinds.md`; expect `docs/spec/vectors-0009.md` from the pca agent.
- `src/renderer/domain/chat/manager.ts`, `peerSession.ts`, `sessions.ts`,
  `messages.ts`, `content.ts`, `identityEvents.ts` (codec), `requests/*`;
  `src/renderer/ui/Search.tsx` (New chat panel), `ChatList.tsx`, `Room.tsx`,
  `RoomHeader`, `Composer.tsx`, `searchSections.ts`.
- `.refs/polkadot-design-system/SKILL.md` §10 (members panel as a side panel,
  no modal; row hover; destructive "Remove" appears on hover).

## Steps

1. **Codec.** Kinds 246/247/248 per the spec; `groupMessage` wraps any
   non-group content using the existing content codec recursively. Poll for
   `vectors-0009.md` (60 s, up to 25 min); decode byte for byte.
2. **Domain.** Dexie tables `groups` (id, name, admin, members[], version,
   createdAt) and a `groupId` column on messages/rooms; a `GroupRoom` peer id
   `group:<uuid>`. `createGroup(name, memberAccounts)`, `sendToGroup(groupId,
   content)` (fan-out over the pairwise sessions; open a request with the
   `groupInfo` as opener where no contact exists), inbound folding with dedup
   by envelope id, roster application (highest version, admin only),
   `leaveGroup`, `updateRoster` (admin). Reject non-members. Specs for every
   rule in the RFC's Testing section over `createInMemoryStatementStore` with
   three identities.
3. **UI.** New chat panel gains "New group": name field, multi-select of
   contacts (checkbox rows), Create. Group rows in the chat list with a
   `Users` icon avatar and "3 members". Room header: name, "3 members ·
   admin <name>", a `Users` icon button opening a members side panel (list
   with status, admin sees Remove on hover and an "Add member" field;
   anyone sees Leave as a Danger button, `rounded-medium`). Messages show
   the sender's name above peer bubbles. Composer and buttons work as in
   1:1 rooms.
4. **e2e.** `scripts/e2e-group.mjs` → `"e2e:group"`: identities a and b
   (existing e2e identities) plus the bot `pcdguide.70`: a creates the group
   with b and the bot, b receives `groupInfo` (`GROUP_JOINED b`), a sends
   "hello all", b and the bot receive it (`FANOUT_OK`), the bot replies and
   both a and b receive the reply with the same envelope id (`BOT_REPLY_OK`),
   a removes b (roster v2; b's client marks itself left: `ROSTER_OK`), print
   `GROUP_OK`. Exit 13 on timeout.
5. **Screenshots.** `group-create.png`, `room-group.png` (three senders, a
   bot reply), `group-members.png` in both themes.
6. **Run**: `npm run check`, `npm run smoke`, `npm run e2e:group`,
   `npm run screenshots`.

## Do not

- No MLS, no group keys, no history transfer, no read receipts in groups, no modal.

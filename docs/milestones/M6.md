# M6 — Desktop conventions, and local agent engines for the Assistant

## Goal

Two halves. (A) The app behaves like a native desktop chat client: send-key
setting, keyboard shortcuts, drafts, honest unread and connection state, native
notifications, a real macOS menu. (B) The Assistant can be answered by a local
coding-agent CLI on this machine (Claude Code, Codex, OpenCode) instead of the
proxy, with tools off by default, using the runner code from `.refs/bot-core`.
Proven by `npm run check`, `npm run smoke`, `npm run e2e:engines`, and updated
screenshots.

## Part A — desktop conventions

1. **Send key setting.** Settings gets a "Chat" section with a Select "Send
   message with": `Enter` (default) or `⌘ Enter`. Stored in Dexie settings
   (`chat.sendKey`). `Composer.tsx`: with `Enter` mode, Enter sends and
   Shift+Enter inserts a newline; with `⌘ Enter` mode, Enter inserts a newline
   and Cmd+Enter (Ctrl+Enter elsewhere) sends. Ignore Enter while an IME
   composition is active (`event.nativeEvent.isComposing`). Esc cancels a reply
   or edit context. Up arrow in an empty composer starts editing your last
   text message in the room.

2. **Drafts.** The composer draft is saved per room in Dexie (`drafts` table,
   keyed by peer id, debounced 300 ms) and restored when the room opens. A room
   with a draft and no newer message shows "Draft: <text>" in the chat list
   preview (mobile string), in `text-fg-secondary`.

3. **Focus.** The composer takes focus when a room opens, after send, and when
   the window regains focus while a room is open (unless a text field elsewhere
   has focus).

4. **Shortcuts** (register in the renderer; document them in Settings under
   "Keyboard"): `⌘K` opens the new-chat/search panel with the field focused;
   `⌘N` same; `⌘,` opens Settings; `Esc` closes the panel or returns to the
   chat list; `⌘↑` / `⌘↓` (and `Alt↑`/`Alt↓`) move to the previous/next chat;
   `⌘1`…`⌘9` jump to the nth chat. Use `metaKey` on macOS and `ctrlKey`
   elsewhere through one helper `isPrimaryModifier(event)`.

5. **Unread, honestly.** A message counts as read only when its room is
   selected AND the window is focused AND the message is scrolled into view
   (use an IntersectionObserver on the last message). A "New messages"
   separator (mobile string) sits above the first unread message when a room
   opens with unread. When scrolled up more than one screen, a round
   jump-to-bottom button (`ArrowDown` icon, `rounded-full`, `bg-surface-container shadow-1`)
   with the unread count appears bottom-right of the flow. The window title
   is "Polkadot Chat" or "(N) Polkadot Chat"; the dock badge shows N
   (`app.dock.setBadge`, via IPC `app:setBadge`).

6. **Connection state, honestly.** Replace the static "Connected" under the
   username with a state from the WS provider: "Connecting…", "Connected",
   "Reconnecting…", "Offline". When not connected for more than 5 s, a
   `bg-surface-nested` banner at the top of the room says "Reconnecting to the
   People chain…" (no button). Add a spec with a fake provider.

7. **Native notifications.** Main process: IPC `notify:show({ title, body, peerId })`
   using Electron `Notification`; clicking it focuses the window and opens the
   room (send `notify:open` to the renderer). Renderer: notify on a new
   incoming message or request when the window is not focused or the room is
   not selected; never for own messages or the Assistant. Settings "Chat":
   "Notifications" Switch (default on) and "Sound" Switch (default on; play
   the system sound via `shell.beep()` in main, no bundled audio). Per-chat
   mute: a `BellOff` toggle in the room header and in the chat list row's
   `DropdownMenu`; muted rows show a small `BellOff` icon; muted chats do not
   notify and do not count in the badge.

8. **macOS menu.** In main, build an application menu with `Menu.buildFromTemplate`:
   app menu (About, Preferences… `⌘,` → sends `menu:settings`, Hide, Quit),
   Edit (Undo, Redo, Cut, Copy, Paste, Select All: the roles, so copy/paste
   works), View (Reload in dev only, Toggle Developer Tools in dev only,
   Actual Size, Zoom In, Zoom Out), Window (Minimize, Close), Help (a link to
   the repo README). Enable spellcheck in `webPreferences` and add a
   `context-menu` handler that shows spelling suggestions and Copy/Paste on
   text fields.

9. **Failed sends.** When the SDK reports a send failure (read how
   `peerSession.ts` surfaces it), the bubble shows a `text-fg-error`
   "Not sent · Retry" line; Retry re-queues the same message id.

## Part B — local engines for the Assistant

10. **Engine model.** `src/main/assistant/engines/` with one module per engine
    and a shared interface:
    ```ts
    type Engine = {
      id: 'proxy' | 'claude' | 'codex' | 'opencode';
      label: string;
      detect(): Promise<{ installed: boolean; version?: string; path?: string }>;
      run(input: { prompt: string; history: Turn[]; systemPrompt: string; sessionId?: string; signal: AbortSignal; onDelta(text: string): void; onEvent(e: EngineEvent): void }): Promise<{ text: string; sessionId?: string }>;
    };
    ```
    `proxy` wraps the existing `client.ts`. `claude`, `codex`, `opencode` are
    ports of the bot-core runners: same CLI args (`claude -p --output-format
    stream-json --include-partial-messages --verbose`, `codex --ask-for-approval
    never exec --json --skip-git-repo-check --color=never --ignore-user-config -C <workspace>`,
    `opencode --pure run --format json --dir <workspace>`), same event parsing
    into text deltas, same session resume (`sessionId` kept per conversation in
    Dexie), same `stripToolMarkup`. Spawn with `buildAgentEnvironment`'s
    approach: a clean env that drops every variable starting with `CLAUDECODE`,
    `CLAUDE_CODE_`, `CODEX_`, `OPENCODE_`, and any `*_API_KEY`/`*_TOKEN` except
    what the engine needs. Workspace: `<userData>/assistant-workspace/`
    (created empty). `EngineEvent` covers `tool_use { name, title }`,
    `thinking`, `done { usage? }`, `error { message }`.

11. **Tool policy.** Port `tool-policy.mjs` (`createToolPolicy`,
    `toolPolicyEnvironment`, capabilities read/write/bash/web/subagents, scope
    workspace). Default: no capabilities. Settings "Assistant" gains "Tools"
    checkboxes (Read, Write, Shell, Web) with the note "Tools run inside the
    assistant workspace folder only" and the same enforcement bot-core applies
    per engine (`assertEngineToolPolicy`, the `--allowedTools` / sandbox flags
    from runners.mjs). The room header for the Assistant shows "tools: off" or
    the enabled list.

12. **Settings UI.** "Assistant" section: an "Engine" Select (Proxy, Claude
    Code, Codex, OpenCode) with a "Detect installed" button that runs
    `detect()` for all and shows version or "not installed" beside each; the
    proxy fields stay for `proxy`; model field only for `proxy`. Store in
    `assistant.json` (`engine`, `tools`).

13. **Room.** While an engine runs, `tool_use` events render as a quiet
    `text-caption text-fg-tertiary` line under the pending bubble ("Reading
    files…", the runner's action title); `thinking` keeps "Thinking…". Stop
    kills the child process (SIGTERM, then SIGKILL after 3 s). The Assistant
    header subtitle shows the engine label ("Claude Code, in this app").

14. **e2e.** `scripts/e2e-engines.mjs` → `"e2e:engines"`: for each engine
    whose `detect()` says installed, run the prompt `Reply with exactly:
    engine ok` with tools off and print `ENGINE <id> ok|fail <first 60 chars>`;
    print `ENGINES_OK` if every installed engine answered, else exit 6. Note:
    Claude Code refuses to start inside another Claude Code session; if
    `claude` fails with that message, print `ENGINE claude skipped (nested
    session)` and do not count it as a failure. The proxy engine runs only when
    `LLM_PROXY_KEY` is set.

15. **Run**: `npm run check`, `npm run smoke`, `npm run e2e:engines`,
    `npm run screenshots` (settings and assistant screens must reflect Part B;
    add `keyboard.png` for the Keyboard section). Look at the PNGs.

## Do not

- Do not change the wire protocol or the identity code.
- Do not give any engine tools by default. Do not run engines outside the
  assistant workspace.
- No modal, no confirm dialog (SKILL.md §10).
- Do not bundle audio files.

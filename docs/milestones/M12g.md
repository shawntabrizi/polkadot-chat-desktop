# M12g — Payments in chat: send and request tokens between people

## Goal

Send PAS to the person you are chatting with, and ask them for PAS, from the
room. No new wire kinds: a **request** is a `buttons` message (spec 0006)
whose one button carries a `tx` intent (spec 0007) that the client built for
a `Balances.transfer_keep_alive` to the requester; a **payment** is the
signer's `transactionReference` (0007) plus the same local reference bubble.
The peer's client, phone or desktop, needs nothing new to see a request as
a button and a payment as a reference. pca bots already understand both.

  "Balances in the UI" (Pocket, balance chip).
- `src/renderer/domain/chain/transactions.ts`, `src/renderer/ui/Transactions.tsx`

  (dry-run and submit), `src/renderer/ui/Composer.tsx` ("+" menu),
  `src/renderer/domain/faucet/dripFlow.ts` (a local flow that ends in a

- Mobile conventions: `docs/reference/mobile-ux.md`; Telegram's "Send
  gift/Stars" and Signal Payments: an amount sheet inline, a confirmation
  strip, a receipt bubble.

## Steps

1. **Send.** Composer "+" menu → "Send PAS" (1:1 rooms whose peer has an
   Asset Hub account: every identity does). An inline amount row in the
   composer area (not a modal): amount field (PAS, 4 dp), an optional note
   (≤ 120 chars), "Review". Review opens the existing signing strip with a
   dry-run of `Balances.transfer_keep_alive(peer, amount)`: fee, the account
   that signs, the balance after. Sign → submit → one `transactionReference`
   to the peer at in block (or failed), with the note in `note`. Locally the
   bubble reads "Sent 1 PAS to <name> · in block #…"; the peer's reads
   "<name> sent you 1 PAS". Refuse when amount + fee + existential deposit
   exceeds the balance ("Not enough PAS: 0.4 available after fees").
2. **Request.** "+" menu → "Request PAS": amount, optional note, "Send
   request". The client builds the intent: `chainId` devnet Asset Hub,
   `calls: [{kind: 0, call: Balances.transfer_keep_alive(me, amount)}]`,
   `display: {title: "Pay <me> 1 PAS", description: note, amount, asset:
   "PAS"}`, `expiresAt: now + 7 d`, and sends a `buttons` message with text
   "Requested 1 PAS · <note>" and one `tx` button "Pay 1 PAS". Own bubble:
   "You requested 1 PAS" with the state: pending, paid (when the peer's
   reference for that intent arrives; match by the reference's `note` or
   call hash, see step 4), expired, declined.
3. **Pay.** The peer's client already renders `tx` buttons with the confirm
   strip (M11). On a request, add: "Decline" as a ghost button beside Pay
   (sends a text "Declined: <title>" so a phone sees it; local state marks
   it declined). After paying, the button reads "Paid".
4. **Matching a payment to a request.** The reference posted by the payer
   carries `note` = the request's message id (spec 0007 `note` is free
   text; put `req:<messageId>` first, then the person's note). The
   requester marks the request paid when a reference with that `note`
   prefix and status 1 arrives, and checks the chain for the amount at the
   best block before showing "Paid". Record the convention in
   `docs/decisions.md` and ask the reviewer to add it to spec 0007.
5. **Groups.** Not in v1 (tx buttons are not pressable in groups; see
   M12 decisions). Split bills come with groups v2.
6. **Balances.** The footer chip and the Pocket refresh after a send (they
   already refresh after signed transactions). The room header shows
   nothing new.
7. **e2e.** `scripts/e2e-pay.mjs` → `"e2e:pay"`: two e2e identities (as in
   `e2e-flip.mjs`); a requests 0.2 PAS from b (`REQUEST_SENT`), b sees the
   button (`REQUEST_SEEN`), b pays (dry-run, sign, `PAID`), a sees the
   reference and marks the request paid (`REQUEST_PAID`), a's balance rose
   by 0.2 (`BALANCE_OK`); then b sends 0.1 PAS to a directly (`SENT`,
   `RECEIVED`). End `PAY_OK`; exit 14 on timeout.
8. **Screenshots**: `send-pas.png` (amount row), `room-request.png` (the
   request bubble with Pay and Decline), `room-request-paid.png`, both
   themes.
9. **Run**: `npm run check`, `npm run smoke`, `npm run e2e:pay`,
   `npm run e2e:typing`, screenshots.

## Do not

- No modal, no new dependency, no new wire kind.
- Never sign without a dry-run. Never send more than the balance minus fee
  and existential deposit.
- Do not edit `docs/spec/*.md`. Questions in `docs/questions.md` "## M12g".

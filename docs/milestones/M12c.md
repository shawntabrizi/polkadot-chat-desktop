# M12c — Submission budget: typing off, seen piggybacks, one reference per tx, measurement

## Goal

Make a 1:1 conversation cost **one Statement Store submission per message**.
The owner ruled (2026-09-23): cut now, while no client in the field sends
these kinds. Spec revisions are already in `docs/spec/0005-typing-and-seen.md`,
`0007-transactions.md` and `efficiency.md` (commit 510e5d7); this milestone
implements them in the desktop. The pca half (another agent, branch
`desktop/rfc-0003`) stops bots sending `typing`, piggybacks their `seen`,
posts one reference per transaction and batches meter charges.

## Steps

1. **Typing off by default.** A new setting "Send typing indicators" (off;
   caption: "Costs one network submission every 10 s while you type"). When
   off, the composer never sends `typing`. When on: first `composing` after
   1 s of editing, refresh at most every 10 s, `until = now + 12 s`
   (`TYPING_INTERVAL_MS`, `TYPING_TTL_MS`). Receiving is unchanged.
2. **Local "working" state for bots.** For a peer whose `botInfo` is known
   (and for embedded bots), the room shows the same working indicator as a
   received `typing{working}` from the moment our message is sent until a
   reply or `deleted` from that peer arrives, or 60 s pass. No wire signal.
   A received `typing` from the bot (older bots) still works and does not
   double the indicator.
3. **Seen piggybacks.** `markRead` queues the `seen` for up to 5 s
   (`SEEN_INTERVAL_MS`). If a message to the same peer is submitted within
   that window, the `seen` goes in the same request statement (one
   submission); otherwise it goes alone at the end of the window. Prove it
   with a unit test that counts submissions on a fake session: "read then
   reply within 5 s" = 1 submission; "read, no reply" = 1 after 5 s.
4. **One reference per transaction.** After signing, post one
   `transactionReference`: status 1 at in block, or 3 on failure. Post
   status 0 only if no block includes it within 30 s. Never post status 2.
   Locally, every reference bubble (own or received) tracks finality from
   the chain (hash + block: finalized when the finalized head passes the
   block and the block is in the finalized chain) and updates its state
   without any message. Received references with status 0 stay pending
   until the chain says otherwise.
5. **Diagnostics.** Count statement submissions and messages sent this
   session in the manager; Settings › Diagnostics shows "Submissions per
   message: 1.00 (12 / 12)". Spec the counter.
6. **Probe.** `scripts/probe-statements.mjs` → `"probe:statements"`: from
   the e2e identity, send text messages to a second e2e identity (both
   e2e children as in `e2e-group.mjs`) at rates 0.5, 1, 2, 4 per second for
   20 s each; the receiver logs arrival times; print per rate:
   submitted, received, p50 and p95 propagation ms, and any submit error
   text. End with `PROBE_DONE`. It must never run against paseo (guard the
   profile). Run it once and put the table in `docs/acceptance.md`.
7. **Identity lookup retry.** Where a request is dropped after
   "identity lookup timed out", retry the lookup once after 5 s before
   dropping; log the retry. Spec it with a fake lookup.
8. **e2e.** Rewrite `scripts/e2e-typing.mjs` for the new rules against
   `pcdpirate.81`: prove (a) no `typing` statement is submitted by us
   (count submissions: our question = 1; the read of the reply plus nothing
   else = 1 more after 5 s), (b) `WORKING_LOCAL` shows at once after the
   send and clears on the reply, (c) `SEEN_RECEIVED` from the bot arrives
   (with or riding on its reply). Exit 0 `BUDGET_OK`, 8 otherwise. The pca
   agent may restart pcdpirate mid-run; if the bot is down, wait and retry
   once. Keep `npm run e2e:meter` and `e2e:flip` green (the bot now sends one
   reference per tx and the settlement may arrive as status 1 only).
9. **Run**: `npm run check`, `npm run smoke`, `npm run e2e:typing`,
   `npm run e2e:meter`, `npm run e2e:flip`, `npm run probe:statements`.

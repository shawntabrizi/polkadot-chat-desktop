# M4 — AI assistant contact via the LLM proxy

## Goal

A built-in "Assistant" contact, local to the app, answered by an LLM through the
Parity LLM proxy (`https://llm.substrate.dev/v1/chat/completions`, OpenAI
format). Replies stream token by token into the room and render as markdown.
Proven by `npm run e2e:assistant`, which sends one prompt through the main-
process client and prints the streamed reply.

## Read first

- `src/main/ipc.ts`, `src/shared/desktop-api.ts`, `src/preload/index.ts`.
- `src/renderer/domain/chat/messages.ts` (message rows), `src/renderer/ui/Room.tsx`,
  `src/renderer/domain/markdown/*`.
- `.refs/bot-core/lib/runners.mjs` lines 1–120 only, to see how bot-core
  shapes a system prompt and streams partial replies (`live-reply.mjs`). Do not
  copy the CLI runners.

## Steps

1. **Proxy client.** Create `src/main/assistant/client.ts`:
   `streamChat({ model, messages, signal, onDelta })` doing a `fetch` POST to
   `${baseUrl}/v1/chat/completions` with `stream: true`, header
   `Authorization: Bearer ${key}`, parsing `data: {...}` SSE lines and calling
   `onDelta(text)` for each `choices[0].delta.content`. `baseUrl` default
   `https://llm.substrate.dev`, `model` default `auto/deepseek-v4.1-flash`.
   The key comes from `process.env.LLM_PROXY_KEY` or from the settings store
   (step 2). Add a spec with a fake `fetch` that yields three SSE chunks.

2. **Settings.** `src/main/assistant/settings.ts`: `{ model, baseUrl, keyEncrypted }`
   in `<userData>/assistant.json`, key encrypted with `safeStorage` like M1.
   IPC: `assistant:getSettings` (never returns the key, only `hasKey: boolean`),
   `assistant:setSettings({ model?, baseUrl?, key? })`.

3. **IPC streaming.** `assistant:send({ conversationId, messages })` starts a
   stream; main emits `assistant:delta { conversationId, messageId, text }`
   events and `assistant:done { conversationId, messageId }` or
   `assistant:error { conversationId, message }`. `assistant:cancel(conversationId)`
   aborts. Typed in `src/shared/desktop-api.ts`.

4. **Renderer.** Add a reserved contact `assistant` (accountId `local:assistant`,
   username `Assistant`) that is not on chain: it appears at the top of Chats.
   Its room reuses `Room.tsx` with a different send path: messages go to
   `assistant:send` with the last 30 turns as context and a system prompt
   ("You are the assistant inside Polkadot Chat. Answer briefly in markdown.").
   Deltas append to a pending message row; `done` finalises it. Rows persist
   in Dexie like any other message (peer = `local:assistant`).

5. **Assistant settings screen.** In `Settings.tsx`: model (text input, default
   shown), base URL, API key (password input; saved through IPC; shows only
   "key stored"). A "Test" button sends "Reply with exactly: proxy ok" and shows
   the result.

6. **e2e script.** `scripts/e2e-assistant.mjs` → `"e2e:assistant"`: uses the
   main-process client directly with `LLM_PROXY_KEY` from the environment,
   sends `Reply with exactly: proxy ok`, prints the streamed text, then
   `ASSISTANT_OK` if the reply contains `proxy ok`, else exits 5.

7. **Run.** `npm run check`; `npm run e2e:assistant`; `npm run dev` and chat
   with the Assistant; record what you saw.

## Do not

- Do not put the key in the renderer, in logs, or in Dexie.
- Do not add tool use, file access, or on-chain actions for the assistant.

## Acceptance

```sh
npm run check
LLM_PROXY_KEY=... npm run e2e:assistant     # streamed text, then ASSISTANT_OK
git status --short
```

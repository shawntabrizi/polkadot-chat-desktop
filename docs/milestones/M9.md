# M9 — Typing and seen (spec 0005)

## Goal

A peer's typing state and an agent's working state show as an indicator, not a
message; own messages advance from delivered to seen when the peer displays
them. Desktop half here; the `pca` half (send `typing{working}` while a turn
runs, send `seen` when a message is consumed, stop faking progress with
placeholder edits when the peer sent `typing`) is a separate agent on the same
branch. No gating: kinds are sent freely (docs/spec/README.md).

## Steps

1. **Codec.** Kinds 240 `typing { until: u64, kind: u8 }` and 241 `seen {
   upTo: String, at: u64 }` in the content model and `ChatMessageCodec`,
   same envelope conventions as kinds 21/242/243. Poll for
   `docs/spec/vectors-0005.md` from the pca agent (every 60 s, up to 25 min);
   decode both vectors byte for byte; if absent, derive and write the file
   with a note.
2. **Ephemeral handling.** Neither kind is stored as a message row, notified,
   counted as unread, shown in previews, or rendered as a bubble. `typing`
   updates an in-memory per-peer state `{ kind, until }`; ignore if `until`
   is in the past or more than 15 s ahead. Any real message from the peer,
   or `typing{stopped}`, clears it. `seen{upTo, at}` marks own messages to
   that peer with `timestamp <= timestamp(upTo)` as `seenAt = at`
   (persisted on the message rows); unknown `upTo` → deferred in a bounded
   per-peer pending set (200), applied when it arrives. Idempotent. Specs
   for each rule.
3. **Sending typing.** When the composer text for a peer changes from empty
   to non-empty, send `typing{composing, until: now+6s}`; refresh at most
   every 4 s while the text keeps changing; on send or clear, nothing (the
   real message clears it) or `typing{stopped}` when the user empties the
   field. Never for the Assistant room. A `settings.chat.typingIndicator`
   switch (default on) turns sending off; receiving always works.
4. **Sending seen.** When the M6 read rule marks messages read (visible +
   focused + in view), send `seen{upTo: <latest displayed message id>, at}`
   at most once per 2 s per peer, only if `settings.chat.readReceipts` is on
   (default: **on**; the owner's rule is no legacy debt, and bots need it).
5. **Rendering.** Room header subtitle: "typing…" (composing) or "working…"
   (agent), in `text-caption text-fg-tertiary` with a three-dot pulse;
   chat-list preview shows "typing…" in place of the last message while
   active. Ticks: `Clock` pending → `Check` sent → `CheckCheck` delivered →
   `CheckCheck` in `text-fg-link` (or the theme's success tone, pick one and
   record it) when seen; tooltip "Seen 3:12 PM". The `pca` placeholder
   frames (`⏳`, `🤔`) keep rendering as thinking rows for bots that do not
   send `typing` yet.
6. **e2e.** `scripts/e2e-typing.mjs` → `"e2e:typing"`: request/accept with
   `pcdpirate.81`, send a question, expect a `typing{working}` from the bot
   before its reply (print `TYPING_RECEIVED kind=working`), then the reply;
   then expect a `seen` for our message (print `SEEN_RECEIVED`); print
   `TYPING_OK`. Print `TYPING_MISSING` and exit 8 if neither arrives in 90 s.
7. **Screenshots.** `room-typing.png` (header "working…", pulse) and
   `room-seen.png` (a seen tick with tooltip) in both themes; use the room
   peer test identity with new `e2e-chat.mjs --typing` and `--seen` flags.
8. **Run**: `npm run check`, `npm run smoke`, `npm run e2e:typing`,
   `npm run screenshots`.

## Do not

- Do not persist or notify ephemeral kinds. No gating. No modal.

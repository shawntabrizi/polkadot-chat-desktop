# M3 — Persistence, restart, macOS package

## Goal

Identity and chats survive an app restart. `npm run package` builds a macOS
Apple Silicon `.dmg` with `electron-builder`. The packaged app passes `--smoke`
and starts with the stored identity.

## Read first

- `.refs/polkadot-desktop/package.json` `build` section and
  `electron-builder` config files (`electron-builder.*`), only for the shape.
- `src/main/identity/store.ts`, `src/main/resources.ts`.
- electron-builder docs are not on disk; use `npx electron-builder --help`.

## Steps

1. **Best-block reads (rule added after M1).** `src/main/identity/directory.ts`
   waits for the finalized block before the first read and reads storage at
   the finalized head; `waitForAttestation` therefore blocks sign-up for extra
   seconds. Change both to the best block: `getValue(..., { at: 'best' })`,
   and wait on `client.bestBlocks$` (first emission) instead of the finalized
   block. Keep a `finalized: boolean` in the sign-up result computed once, non-
   blocking, and show "confirmed" vs "finalizing" in the UI. Add a spec with a
   fake client. Apply the same rule to any chain read M2 added (grep for
   `finalized`). Also: (a) cache the runtime metadata on disk under
   `<userData>/metadata/<genesis>.bin` the way `.refs/bot-core/lib/chain-client.mjs`
   does, so the first read after start does not wait minutes for a public
   node to serve metadata (the M2 e2e timed out three times on this);
   (b) when a read times out, retry once on the next endpoint of the profile;
   (c) in `src/renderer/domain/identity/lookup.ts` read `Resources.Consumers`
   at `{ at: 'best' }` through the app's People connection instead of
   host-papp's default-block read.

2. **Restart safety.** On start, main loads the identity; the renderer, before
   showing Chats, checks Dexie has the three secrets and the `userIdentity`
   row, and re-seeds from `identity:secretsForRenderer` when any is missing.
   Add a spec.

3. **Logout / reset.** Add `identity:reset` IPC: deletes `identity.json` and
   tells the renderer to `db.delete()` and reload. Settings screen gets a
   "Reset identity" button behind a confirm. Add a spec for the renderer part.

4. **electron-builder.** Add `electron-builder` `26.15.3` as a devDependency.
   Add `electron-builder.yml`: `appId: dev.shawntabrizi.polkadot-chat`,
   `productName: Polkadot Chat`, `directories.output: dist`, `files: [out/**, package.json]`,
   `extraResources: [{ from: resources, to: resources }]`, `mac: { target: [dmg], arch: [arm64], category: public.app-category.social-networking, identity: null }`
   (unsigned). `resourcePath()` from M1 must find the wasm under
   `process.resourcesPath/resources` in the packaged app.
   Script: `"package": "npm run build && electron-builder --mac --arm64"`.

5. **Smoke on the package.** Add `scripts/smoke-packaged.sh`: finds
   `dist/mac-arm64/Polkadot Chat.app`, runs
   `"dist/mac-arm64/Polkadot Chat.app/Contents/MacOS/Polkadot Chat" --smoke`,
   expects `SMOKE_OK`. Script `"smoke:packaged": "bash scripts/smoke-packaged.sh"`.

6. **Electron binary after install.** A fresh `npm install` in a new checkout
   left `node_modules/electron/dist` empty (seen 2026-09-23 in a git worktree;
   `electron-vite dev` then fails with "Electron uninstall"). Add a
   `"postinstall": "node node_modules/electron/install.js"` script guarded so
   it is a no-op when `dist/` already exists, and mention it in README.md.
   Keep the existing `prepare` (papi generate) script.

7. **Window state.** Remember window size and position in
   `<userData>/window.json` (no new dependency).

8. **Run.** `npm run check`, `npm run package`, `npm run smoke:packaged`.

## Do not

- No code signing, notarization, or auto-update.
- No Windows or Linux targets.

## Acceptance

```sh
npm run check
npm run package            # dist/*.dmg exists
npm run smoke:packaged     # SMOKE_OK
git status --short
```

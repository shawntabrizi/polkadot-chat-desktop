# M17 — Bot directory (spec 0010)

**Sizing: medium; smaller than M12, larger than M12i.** No chain work, no
contract, no new dependency (sr25519 verify and BLAKE2b are already in the
tree). New in three places: a codec with signature checks, a directory
subscription with a checked local table, and a Bots tab that replaces the
demo manifest. The pca half is small: one card builder, two commands, a
timer and a watch. Two sub-steps that each land green: **M17a** codec +
pca publishing + a directory probe script (proves the rail), **M17b**
desktop Bots tab + migration + the e2e below. The DotNS `chat.bots` record,
shared report lists, and card bubbles in chats are **not** in M17.

## Goal

On devnet, the six demo fleet bots (`pcdpirate.81`, `pcdguide.70`,
`pcdmeter.01`, `pcdflip.44`, `pcdpeer.47`, `pcdcolor.05`; `pcdfaucet.77`
is being retired, roadmap 2026-09-24, and publishes no card)
publish signed bot cards on the directory topic, each with an operator
claim from one fleet operator identity. A fresh desktop profile **with no
built-in manifest** opens the Bots tab, lists all six with name, tagline,
tag, price and "Run by @operator", searches them, and starts a chat with
one. Desktop half: this repo. `pca` half (another agent, branch
`desktop/rfc-0003`).

## Steps — pca half (M17a)

1. **Codec.** `encodeBotCard` / `decodeBotCard`, the three topics and the
   channel, the operator message; pin `vectors-0010.md` B1, B2, B3 and the
   negative checks in `bot-core/test/codec.test.mjs`. Verify B2's signature
   with the operator key; sign-then-verify for fresh claims.
2. **Config.** New optional bot config fields `tagline`, `tags`, `pricing`,
   `operator` (the claim). The card's `name`, `kind`, `info` come from the
   bot's current botInfo document; `info.hash` = blake2b_256 of its content
   bytes.
3. **`pca operator-sign <bot> --operator <secret file>`** writes the claim
   (one-year `validUntil`); **`pca publish-card <bot>`** builds, checks the
   limits, refuses an allowlisted bot, submits with expiry
   `(now + 72 h) << 32`, prints card hash, topics, expiry. `pca info` shows
   "card: live, expires in 71 h" or "card: missing".
4. **bot-core.** Publish on start, on a config change (≤ 1 per hour), every
   24 h. Watch `cardTopic(self)` with the ingress supervisor (like the
   heartbeat); re-publish on `BOT_CARD_MISSING`. `BOT_CARD=0` turns it off.
   Log `BOT_CARD_PUBLISHED {hash, expiresAt}`.
5. **Fleet.** Create one lite identity for the fleet operator on devnet
   (name chosen by the owner; `pcdops.NN` in the vectors is a placeholder),
   sign the six claims, set the taglines, tags and prices from today's
   `BUILT_IN_DEMO_BOTS`, deploy, publish.
6. **Probe.** `scripts/probe-directory.mjs` (pca repo): subscribe
   `matchAll([directoryTopic])` from a fresh connection, decode, print one
   line per card and `DIRECTORY_COUNT n`. Expect 6.

## Steps — desktop half (M17b)

1. **Codec.** `src/renderer/domain/directory/card.ts`: decode, limits,
   topics, operator message, sr25519 verify; spec pins every vector and
   negative check.
2. **Domain.** `directory.ts`: subscribe while the Bots tab or the
   onboarding pane is open; keep the newest card per signer; batched
   best-block checks (`UsernameOwnerOf` for bot and operator, `Consumers`
   for chat key and credibility); a Dexie table `botCards` (signer, card,
   hash, firstSeenAt, checkedAt, state) and `hiddenBots`; ranking and
   search per the RFC as pure functions with specs. Specs run over
   `createInMemoryStatementStore` with a forged-username card, an expired
   card, a bad operator signature and two cards from one signer.
3. **UI.** Left pane gains a **Bots** tab: search field, tag chips, rows
   (avatar, name, `BotBadge`, tagline, price, operator line with person
   mark, Start chat / Open), "Show more" per 20, Hide on hover with Undo.
   Row click opens a detail pane (a `Selection` kind `bot`). Global search's
   Bots section adds directory hits. Empty state: "No bots on this network
   yet."
4. **Migration.** Delete `BUILT_IN_DEMO_BOTS`, `parseDemoManifest`,
   `src/main/demoManifest.ts`, `PCD_DEMO_MANIFEST_URL`, the `demo:bots`
   IPC and Settings › Demo. Keep the M12i start logic
   (`startDemoChats`, the key-visible wait, idempotency) but feed it the
   directory entries whose checked operator is in `DEMO_OPERATORS[profile]`
   (one account per profile; Paseo empty). The onboarding pane becomes
   "Meet some bots": the first page of the Bots tab plus "Start chats with
   all" for those entries. Record the removal in docs/decisions.md.
5. **e2e.** `scripts/e2e-directory.mjs` → `"e2e:directory"`: a fresh
   profile (no manifest code path exists any more) opens the Bots tab; wait
   up to 60 s for six checked cards (`DIRECTORY_LISTED 6`); each shows
   the fleet operator (`OPERATOR_OK`); search "flip" returns only
   `pcdflip.44` (`SEARCH_OK`); Start chat with `pcdpeer.47`, send "hi",
   receive the echo (`CHAT_OK`); Hide `pcdcolor.05`, reload, it stays
   hidden (`HIDE_OK`); print `DIRECTORY_OK`. Exit 13 on timeout.
   `e2e:demo` is updated to the directory source and must still pass.
6. **Screenshots.** `bots-tab.png`, `bot-detail.png`, `demo-onboarding.png`
   (new source) in both themes; fixture cards for the shots.
7. **Run**: `npm run check`, `npm run smoke`, `npm run e2e:directory`,
   `npm run e2e:demo`, `npm run screenshots`.

## Do not

- No DotNS reads or writes; no card bubble in chats (kind 251 as content);
  no shared report lists; no usage counts; no indexer; no avatar field.
- No change to the heartbeat, to `botInfo`, or to any chat kind.
- Do not keep a fallback to the built-in list: the goal is that the list
  comes from the network.

## Risks

- **Eviction:** a bot at its allowance loses the card first (lowest expiry).
  The watch in pca step 4 covers it; the e2e prints the fleet's live
  statement counts if a card is missing.
- **Lite-person sybil bound** is unknown; it does not block M17 (the fleet
  is ours) but decides the default ranking later.
- **Propagation:** a card submitted on one node must reach the desktop's
  RPC node; the probe step measures it before the desktop half starts.

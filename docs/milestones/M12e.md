# M12e — Chat management, lenient buttons parsing, small fixes

## Goal

The owner made a request to a bot that will never accept, and cannot remove
it. A room today offers mute, block, report, decline (incoming) and leave
(group). This milestone adds the missing local chat management, brings the
desktop's own buttons parser to the leniency pca now has (spec 0006, "Host
parsing leniency"), and closes two small items.

## Steps

1. **Delete chat** (room menu and chat-list row menu): removes the room, its
   messages, drafts, reactions and a pending outgoing request from this
   device, after a 6 s Undo. The peer keeps their copy. If the peer accepts
   later or writes, the chat comes back as a fresh request or room. Groups:
   delete = leave (if a member) then remove locally.
2. **Withdraw a pending request**: the same action on a pending outgoing
   row, labelled "Withdraw request"; stop any resubmission; the statement
   expires in the store. Pending rows show "No answer yet · sent 3 d ago".
3. **Archive / unarchive** (hidden "Archived" section at the bottom of the
   list, collapsed; unread still counted in the badge).
4. **Pin / unpin** to the top of the list, at most 5, pinned order stable.
5. **Mark as unread / mark as read** on a row.
6. **Clear history** (keeps contact, session and room; messages removed
   locally after Undo).
7. **Nickname** for a contact (local label shown as the name; the username
   stays visible next to it in `text-fg-tertiary`; search matches both).
8. **Forward** a message to another chat: a copy of the content sent as a
   new message with a local "Forwarded" caption (no wire change; the text
   is prefixed with nothing). Buttons and tx intents are not forwarded
   (text only, with the keyboard's menu-as-text fallback).
9. **Blocked list** in Settings › Privacy with Unblock.
10. **Lenient buttons parsing in the desktop**: port pca's
    `extractButtonsBlock` semantics to `src/shared/buttonsBlock.ts`
    (bare/`json`/`buttons` fence, flat array as one row, block anywhere with
    the surrounding text kept, last valid fence wins, invalid button-looking
    block stripped and logged to the console), used by the Assistant's
    `replyContent`; `streamingFence` hides an open untagged or `json` fence
    whose first non-space character is `[` or `{` the same way it hides a
    `buttons` fence. Tests mirror pca's, including the owner case.
11. **Block explorer caption**: the Polkadot.js Apps option gets the caption
    "May not decode newer runtimes" (it fails on Paseo Asset Hub today).
12. **Diagnostics counters** move to the main process so a window reload or
    theme switch does not zero them.
13. **Run**: `npm run check`, `npm run smoke`, `npm run e2e:typing`,
    `npm run e2e:chat`; screenshots `chat-menu.png` (row menu open),
    `archived.png`, `settings-privacy.png` in both themes.

# Review: spec 0013 Capabilities and 0014 Bulletin FileVariant (abbb962) — accepted with one open rule (2026-09-24)

0013: kind 252 `capabilities` (43-byte content: version, a bitmap of supported kinds, file variants, HOP dialects, feature flags), sent per device on its own session riding a message that goes anyway; stored per (peer, device), dropped on DeviceRemoved; a silent device is baseline; senders use the intersection over the peer's devices (Signal's all-devices rule). 0014: our Bulletin file as `FileVariant` index 1 inside `RichText`; kind 250 retired one release after M20. Vectors computed by two encoders (Python, scale-ts) and agreeing; pca to confirm.

Verified facts that shape the rollout:
- An unknown `FileVariant` index makes the WHOLE message unsupported on Android and iOS (caption lost; Android re-parses after an update). So the Bulletin variant goes only to devices that advertised it.
- A `capabilities` message shows on a baseline phone as one "Unsupported message" bubble per sending device per chat. No carrier the phones skip is known.

Open rule (needs the owner's phone check): whether the phones already show unsupported bubbles for the read receipt (`seen`) the desktop piggybacks today. If yes, adopt "send extension kinds only after the peer has shown one" (bots exempt) for capabilities and seen alike; if no, find what the phones do with unknown kinds in a batch before sending capabilities to phones.

M20 first checks stand: the SDK's `RequestMessage` does not expose the sending device; this must be solved (or capabilities keyed by session) before the multi-device rule can work.
